Implement a complete PROFESSIONAL CERTIFICATE SYSTEM for the Nyaya Nagri game.

GOAL:
Whenever a player completely finishes a learning zone, automatically generate and unlock a professional certificate for that specific zone. The certificate must appear inside "My Progress" and the player must be able to view and download it.

IMPORTANT:
Do NOT create a fake/static certificate screen.
This must be connected to the actual zone completion/progress system.

==================================================
1. ZONE COMPLETION → CERTIFICATE UNLOCK
==================================================

Use the existing zone/progress system.

For every learning zone, determine whether the player has actually completed ALL required activities/content for that zone.

Example zones can include:
- Know Yourself / Right to Childhood
- School Rights
- Family & Community Shield
- Justice System Simulator
- Digital Safety
- Any other zones already present in the project

Do NOT hardcode a certificate as completed.

Certificate should unlock ONLY when:

zoneProgress.completed === true

or when all required activities/tasks/lessons for that zone are completed according to the existing project logic.

When a zone becomes fully completed:
→ mark certificate as unlocked
→ save certificate information
→ make it visible inside My Progress

The certificate must NOT unlock merely because the user visits the zone.

==================================================
2. CERTIFICATE DATA
==================================================

Create a structured certificate object for every completed zone.

Example:

{
  id: "digital-safety-certificate",
  zoneId: "digital-safety",
  title: "Certificate of Completion",
  zoneName: "Digital Safety",
  recipientName: "Aditya",
  completedAt: "...",
  certificateId: "...",
  unlocked: true
}

Use the player's existing game nickname/profile name.

IMPORTANT:
The user's real personal information should NOT be requested just for the certificate.

Use the existing player name/nickname already stored in the game.

If the player changes their game nickname, make sure the certificate displays the appropriate current/stored player name according to the existing profile logic.

==================================================

Complete the zone to unlock your certificate.

==================================================
4. PROFESSIONAL CERTIFICATE DESIGN
==================================================

The certificate itself must look like a REAL professional educational certificate.

Do NOT make it look like a basic web card.

Design direction:

- Premium educational certificate
- Clean white/ivory paper background
- Elegant navy blue + gold visual identity
- Nyaya Nagri branding
- Subtle legal/scales-of-justice visual elements
- Thin decorative gold border
- Professional typography hierarchy
- Large "Certificate of Completion"
- Recipient name should be the visual focal point
- Zone/course title clearly displayed
- Professional spacing and alignment
- Subtle ornamental corners
- Elegant seal/badge
- Digital signature area
- Certificate ID
- Completion date
- High-quality print-ready appearance

The design should feel like something a student would genuinely want to download and share.

Avoid:
- childish UI
- excessive gradients
- neon colors
- excessive rounded cards
- gaming-style certificate
- clutter
- emojis
- oversized decorative elements

The certificate should feel premium while still belonging to the friendly Nyaya Nagri brand.

==================================================
6. CERTIFICATE ID
==================================================

Generate a unique certificate ID for every certificate.

Example format:

NYN-DIG-2026-A8F42C

or another clean unique format.

The ID should remain stable after generation.

If the user refreshes the page or returns later, the same certificate ID
must still be shown.

Do NOT generate a new ID every time the certificate is opened.

==================================================
7. COMPLETION DATE
==================================================

When the zone is completed for the first time:

save the completion timestamp.

Use that saved timestamp as the certificate completion date.

Opening the certificate later must NOT change the completion date.

Format it professionally, for example:

10 August 2026

The certificate should appear centered on screen.

Desktop:

- professional modal/page layout
- enough whitespace around certificate
- clear controls

Mobile:
- responsive certificate preview
- allow scrolling/zooming if necessary
- maintain certificate proportions

Controls:

[Download Certificate]
[Close / Back]

Do NOT make the certificate preview look like a normal game popup.

==================================================
9. DOWNLOAD FUNCTIONALITY
==================================================

The user must be able to download the certificate.

Preferred result:

A high-quality PDF certificate.

Filename example:

Nyaya-Nagri-Digital-Safety-Certificate.pdf

The downloaded PDF should contain:
- Nyaya Nagri branding
- recipient name
- zone name
- completion date
- certificate ID
- certificate design
- professional border/decorations
- signature/seal area

Make sure the PDF is actually downloadable and not just a screenshot.

If the current architecture makes PDF generation difficult, implement a reliable
client-side certificate generation approach while preserving the professional
print quality.

The downloaded certificate should be suitable for:
- saving
- printing
- sharing

==================================================
10. CERTIFICATE STATE PERSISTENCE
==================================================

Persist earned certificates using the project's existing persistence system.

If the project currently uses localStorage, integrate with the existing localStorage
architecture instead of introducing an unnecessary backend.

If the project already has a database/backend, use the existing persistence layer.

The certificate must survive:
- page refresh
- browser restart
- returning to the game

Do NOT duplicate certificates after refresh.
