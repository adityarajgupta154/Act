IMPLEMENT REAL-TIME VOICE CONVERSATION FOR NYAYA AI

I want Nyaya AI to behave like a REAL voice assistant, not a normal
chatbot with a microphone button.

The user should be able to:

1. Tap the Nyaya AI robot.
2. Start speaking naturally.
3. Gemini should listen continuously.
4. Gemini should understand the user's speech.
5. Gemini should generate a response.
6. The response should be spoken aloud naturally through the robot assistant.
7. The user should be able to interrupt Gemini while it is speaking.
8. The conversation should continue naturally without requiring the user
   to press a Send button after every sentence.

==================================================
USE GEMINI LIVE API
==================================================

Use Google's current Gemini Live API for real-time bidirectional
voice interaction.

Do NOT implement this as:

Speech-to-Text
→ normal Gemini request
→ Text-to-Speech

That approach is NOT the desired experience.

Use the Gemini Live API/WebSocket architecture for a persistent
real-time audio conversation.

The architecture should be:

Browser microphone
        ↓
Live API session
        ↓
Gemini
        ↓
Native audio response
        ↓
Browser audio playback

Use the official @google/genai SDK/current Live API implementation.

==================================================
VOICE MODEL
==================================================

Use the currently supported Gemini Live voice model available in the
project/account.

Prefer the current low-latency Live model rather than an old
generateContent-only model.

The assistant should use native AUDIO response modality.

Configure a friendly, warm, clear voice suitable for a child-focused
educational application.

The voice should sound:

- friendly
- calm
- natural
- encouraging
- conversational
- not robotic
- not overly dramatic

==================================================
INTERRUPTION
==================================================

This is VERY IMPORTANT.

If Nyaya AI is speaking:

"Your right means that..."

and the user says:

"Wait, what does that mean?"

Nyaya AI must immediately stop/interrupt the current response
and listen to the user.

Do NOT force the user to wait until the AI finishes speaking.

Use Live API interruption/VAD behavior.

When an interruption occurs:

1. Stop current audio playback.
2. Preserve the conversation context already received.
3. Process the new user speech.
4. Respond to the new question.

==================================================
AUDIO FORMAT
==================================================

Follow the official Gemini Live API audio requirements.

Capture microphone audio as:

16-bit PCM
16 kHz
little-endian

Send audio chunks continuously to the Live API.

Receive Gemini's native audio response.

Live API audio output is 24 kHz PCM.

Implement proper audio buffering/playback so there are no:

- clicks
- gaps
- distorted audio
- overlapping responses
- audio corruption

==================================================
AUDIO PLAYBACK
==================================================

Use Web Audio API / AudioContext appropriately.

Create a reliable audio playback queue.

When Gemini sends multiple audio chunks:

chunk 1
chunk 2
chunk 3
chunk 4

play them continuously in order.

Do NOT create a new Audio element for every chunk.

Avoid gaps between chunks.

When interrupted:

clear pending audio chunks immediately.
