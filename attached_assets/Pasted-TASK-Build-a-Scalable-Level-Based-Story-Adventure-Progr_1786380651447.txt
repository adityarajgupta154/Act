TASK: Build a Scalable Level-Based Story Adventure Progression System

I want to completely upgrade the existing "Story Adventure" inside Nyaya Nagri.

IMPORTANT:
This is NOT a redesign of the entire game.
Keep the existing map, player, AI assistant, UI, story slides and existing Level 1 functionality.

The main change is to convert Story Adventure into a scalable level-based progression system similar to the progression experience of Candy Crush:

Level 1 → Complete → Level 2 Unlocks
Level 2 → Complete → Level 3 Unlocks
Level 3 → Complete → Level 4 Unlocks
...
and so on.

I will eventually add MANY story levels, so build this as a reusable data-driven system rather than hard-coding individual levels.

==================================================
1. STORY ADVENTURE ENTRY
==================================================

When the player approaches/enters the Story Adventure location:

Open a dedicated Story Adventure Level Selection screen.

The player should NOT immediately be thrown into a story.

Instead show a beautiful level progression map.

Example:

        🔒 Level 5
           |
        🔒 Level 4
           |
        🔒 Level 3
           |
        ⭐ Level 2
           |
        🏆 Level 1

Level 1 should be unlocked initially.

All future levels should appear locked.

==================================================
2. CANDY-CRUSH-STYLE PROGRESSION
==================================================

Create a vertical/curved adventure path containing story levels.

Each level should be represented by a beautiful circular/rounded level node.

States:

A. CURRENT / UNLOCKED
- bright
- glowing
- subtle pulsing animation
- clearly clickable
- show level number
- show level title

B. COMPLETED
- gold/green success appearance
- checkmark or trophy
- subtle sparkle animation
- show reward earned
- visually indicate completion

C. LOCKED
- muted appearance
- lock icon
- slightly faded
- NOT clickable
- show "Complete previous level to unlock"

The progression should visually communicate:

Level 1 completed
        ↓
Unlock animation
        ↓
Level 2 becomes available

3. UNIQUE UNLOCK ANIMATION
==================================================

When a player completes Level 1:

Do NOT instantly switch to Level 2.

Create a satisfying unlock sequence.

Suggested animation:

1. Level 1 completion screen appears.

2. Show:
   "Right to Life Unlocked!"
   
3. Trophy/badge animation.

4. Small particles/sparkles appear around the completed level.

5. Camera/path visually moves toward the next locked level.

6. The Level 2 lock begins glowing.

7. Lock shakes slightly.

8. Lock opens with a smooth animation.

9. Level 2 node transforms from LOCKED → UNLOCKED.

10. Show:
   "New Adventure Unlocked!"
   
   "Level 2 — Clean Water, Healthy Life"

11. Add a small "PLAY LEVEL 2" CTA.

12. Only after this animation finishes should Level 2 become clickable.

Animation should feel playful and rewarding, inspired by mobile adventure games, but DO NOT copy Candy Crush assets or branding.

==================================================
4. IMPORTANT: DO NOT AUTO-START LEVEL 2
==================================================

After Level 1 completion:

Do NOT automatically start Level 2.

Instead:

      ↓
Level 2 node becomes clickable
      ↓
User chooses to enter Level 2

This gives the child control.

6. LEVEL UNLOCK LOGIC
==================================================

Implement proper persistent progression.

Initial state:

Level 1 = unlocked
Level 2 = locked
Level 3 = locked
Level 4 = locked
...

When Level 1 is successfully completed:

Level 1 = completed
Level 2 = unlocked

When Level 2 is successfully completed:

Level 2 = completed
Level 3 = unlocked

Continue automatically.

Persist the progress so that refreshing the browser does NOT reset unlocked levels.

Use the existing project's persistence/database system if available.

If the current project uses localStorage for player progress, integrate with that rather than introducing unnecessary new infrastructure.

Store something similar to:

storyAdventureProgress = {
  completedLevels: [1],
  unlockedLevels: [1,2]
}

After Level 2:

completedLevels: [1,2]
unlockedLevels: [1,2,3]

Make sure this works correctly even after page refresh/reload.
