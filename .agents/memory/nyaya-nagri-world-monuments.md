**Rule:** Zone landmarks are transparent cutout PNGs rendered at NATIVE size (1 file px = 1 world px, U=40px/unit); `ZONE_ART` in the monuments module must equal the file's exact pixel dims, and the code-side extras — gold ring, padlock, label pill — are sized FROM `ZONE_ART.w`. Never bake text, locks, or pads into the PNG. The grey stone pad + code-drawn ground shadow are GONE (explicit user task, Aug 2026): monuments sit directly on the grass — never re-add ANY platform/shadow layer under a monument; the art's own feathered grass halo is the only grounding. Label pills keep the historical pad-front offset via the retained PAD_ZONES set.

**Why:** The Aug 2026 "Right to Childhood" crystal→sanctuary replacement worked first try because the asset was only art; the engine supplied every stateful/UI element. A baked label or lock would double up with the code-drawn ones.

**How to apply (replacement recipe):**
1. `generateImage` with `removeBackground: true`, `resolution: 'high'`, prompt pinned to the map's look ("bright cartoon mobile-game landmark, gentle top-down three-quarter perspective, clean edges, no text, no letters, no lock icons, no UI, plain background") + concept symbols. NOTE: the map's baked shadows assume sun UPPER-RIGHT (shadow lower-left) — prompt lighting accordingly.
2. `magick <raw> -trim +repage -resize 172x -bordercolor transparent -border 4 <dest>` → lands in the monument family scale (existing family: 158-200w × 159-270h). Verify `alpha=Blend`.
3. Save under the world assets dir as `monument-<concept>.png`, update the Vite import + assets map (PhaserWorld) and `ZONE_ART` (key + exact new file WxH). Delete the old PNG (grep for its key first — smokes don't assert monument PNGs as of Aug 2026) and RESTART the web workflow (delete→stale vite module graph quirk).
4. Verify in-game with the TEMP-SCREENSHOT App harness (dev-testing memory) at viewport **2400x2960** — from spawn that covers the ENTIRE zone ring in one shot, perfect for style/scale comparison against neighbor monuments; Phaser falls back to Canvas2D headless and screenshots fine.

Zone identity colors live in the label pills (`LABEL_COLORS`), not the art — replacing art does not require touching pill colors.

**User-uploaded "transparent" PNGs (Aug 2026 swaps):** ChatGPT-exported images can have the backdrop BAKED IN — checkerboard OR solid black (srgb, alpha=Undefined) — always `magick identify` before trusting claimed transparency; the platform bg-removal callback handles both cleanly (verify edges on a solid-color flatten). To swap art WITHOUT moving the label pill/ring (both derive from `ZONE_ART.w`): land the final file at the OLD width exactly (`-resize <w-8>x` + 4px transparent border) and overwrite the same filename — only `h` changes, zero import/key churn, no duplicate-sprite risk.
User art with a BAKED label plaque: crop the plaque off — the engine pill is the map-wide label system and the swap tasks themselves prefer it ("no two labels"). Locate the cut line by the plaque's UNIQUE color (per-row scan for that hue + confirm other elements' row ranges end above it); a mean-alpha row profile finds no gap when art touches the plaque band. Decorative security icons (mini locks/shields) in user art stay verbatim even though the state padlock doubles the motif while locked — their pixels, disclosed, not a bug.

**Story Adventure house is the exception:** it is NOT a ZONE_ART monument — it's the `decor-house` sprite rendered at NATIVE texture size (no dims registry), its name pill sits at a FIXED offset (not width-derived, so no width pinning needed), and tick/hit-area/collision adapt or are constants. Swapping it = overwrite the PNG only, zero code. HOUSES must stay single-entry, else the shared texture duplicates the building.

## Roads are DERIVED — plaza-disc swap has a lockstep constant
Road lanes (roads.ts) compute endpoints from zones.ts + storyData STORY_ENTRANCE — moving/adding a location updates its road automatically; never hand-tune spoke coordinates again. BUT the plaza junction hides lane starts under the disc using rim half-extents PLAZA_RX/PLAZA_RZ = plaza-disc.png (w/2)/U and (h/2)/U. **Why:** lanes draw UNDER the disc (depth 0.5 vs 0.6), so a plaza-disc art swap that changes dimensions without updating these constants leaves visible lane-start seams or floating gaps at the junction. **How to apply:** any plaza-disc.png replacement (same recipe as monument swaps) must update PLAZA_RX/RZ in plazaGeom.ts (moved out of roads.ts Aug 10 2026 — Phaser-free so engine.smoke unit-tests the ellipse hub-exclusion rule) in lockstep, then re-shoot the 2400x2960 ring.

Aug 10 2026 realignment: ALL lanes are STRAIGHT (bow 0) — the user-approved reference is a clean radial wheel (N/S vertical, W/E horizontal, mirrored diagonals; zones.ts positions already encode the symmetry). Never reintroduce per-lane bows: curved diagonals READ as the "crooked roads" bug. laneSpecs is ZONES-derived (every zone outside the plaza disc auto-gets a spoke; new location = zero road code); terminus fit is data-only STOP_OVERRIDES. Tuning method: full-ring 2400x2960 shot + 360px terminus crops; feathered-halo cutouts (kindness stone, help house) need ~0.45u deeper stops than fence/plinth arts or a ~0.3u grass gap shows at the tip.
